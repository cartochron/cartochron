Cartochron field manual

A practical guide to recording runs, interpreting gaps, comparing routes in space and time, and inspecting observed positions.

What the map can tell you. A line connects recorded fixes within the same recording run; it is not proof of movement along every point of the line. Time means server receipt time, not necessarily the GPS fix acquisition time. A geographic crossing is not evidence of a meeting, and an absent fix does not prove an absence.

1. Choose and compare recording runs

Choose a focused run in Track, then switch to History. Use Tracks to show up to three additional runs (four total). The focused run stays blue, while comparisons use outlined violet, teal, and crimson routes. Hover or click a route node to inspect the recorded timestamp and coordinates.

Entire runs (spatial) displays each comparison run across its own loaded history; Same interval applies the focused run's selected From/To time window to every comparison. The displayed data is paginated; inspect the Load more and partial-results messages before drawing conclusions.

2. Recognize recording gaps

Cartochron splits a drawn route when consecutive observations are more than 10 minutes apart. Pale gap-end rings mark the last fix before and first fix after missing data. Click either ring or move Inspect point to one of its endpoints to read the duration.

In the demo, demo-city-loop includes a deliberate 21 minute 30 second interval without observations. The gap is about time; it does not establish that the source stopped moving. Shorter missing intervals are not flagged by this fixed display rule.

3. Inspect several runs at the same time

In History, adjust Shared time along the bottom. For each visible run, the map highlights the most recent actual fix at or before the cursor only if it is at most five minutes old. Older or absent observations show as no recent fix. This is not interpolation or location prediction.

The shared cursor spans the observations currently loaded in the browser, including comparisons. If a run is paginated or capped, the cursor does not represent its entire database history. For closer investigation, choose a narrower interval and load the necessary pages.

4. Inspect a selected place

Open Inspect place in History, select a 50, 100, or 250 metre radius, then click a location on the map. The browser lists the loaded observations inside the circle in chronological order, with their run IDs and distances. Up to 40 results are listed.

This is a local inspection of already loaded observations, not a database-wide search. If a track has no observations near the selected location, that says nothing about unrecorded movement or earlier pages you have not loaded. Distance is computed from reported coordinates without GPS accuracy metadata.

5. Reproducible manual field checks

Start with synthetic data, not a real person's location. Use separate files for the fixture and the receiver; never overwrite an existing observation database.

python3 demo.py --db /tmp/cartochron-source.sqlite3
python3 map_server.py --db /tmp/cartochron-source.sqlite3

Select demo-city-loop for gaps and demo-crossing for route comparison. Select demo-long-history for pagination, and demo-single-point for a run with no drawable line.

For a live ingestion rehearsal, stop the first server, then run:

python3 map_server.py --db /tmp/cartochron-receiver.sqlite3
# In a different terminal:
python3 replay.py --db /tmp/cartochron-source.sqlite3 --count 30 --interval 1

In Live, choose demo-replay and check that new points appear. Then switch to History to verify that those observations are still queryable. Run make check for Python, Ruby, and optional Node.js regression tests.

Privacy and operation. Location histories are sensitive. The default memory-only server discards observations on exit. Persistent mode uses a private SQLite file. Exposing a network listener requires appropriate authentication and an encrypted transport (TLS reverse proxy or trusted VPN). Operate only with authorization and a defined retention policy.
